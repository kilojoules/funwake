# Model & CLI-version forensics (from archived transcripts)

Ground truth is the transcript `model` field, not the runner config
(`harness/models.json` is the LUMI open-weights vLLM config — gemma/qwen/llama —
irrelevant to the hosted Claude/Gemini runs).

## Claude flagship (schedule-only, dual-bump `iter_192`)

Model strings across the 49 archived sophia transcripts:

| count | model | role |
|--:|--|--|
| 1383 | `claude-opus-4-5-20251101` | primary (400 main-session + 983 subagent) |
| 372 | `claude-sonnet-4-5-20250929` | some full main sessions |
| 34 | `claude-opus-4-6` | **late sessions only (Apr 18–19)** |
| 12 | `claude-haiku-4-5-20251001` | background (subagents) |

Claude Code version: `2.1.0` (3167 msgs) + `2.1.78` (66 msgs).

**iter_192 (the dual-bump) attribution.** attempt_log places attempt 192 at
**2026-04-05 13:09** (matches the local `iter_192.py` mtime 13:02); the full
423-attempt log runs 2026-04-05 → 04-26. The sophia transcripts (Apr 18–19) are
a **later continuation** — they do not contain iter_192, whose original session
was local and fell outside the CLI's ~30-day retention (unrecoverable).

By date, `claude-opus-4-6` is excluded (it appears only in the Apr 18–19
sessions). So the dual-bump was generated by **`claude-opus-4-5-20251101` or
`claude-sonnet-4-5-20250929`**, most plausibly the primary Opus 4.5. This
**corrects** the earlier heuristic forensic guess of Opus 4.6, which is ruled
out on dates.

## Gemini flagship (schedule-only)

Single model, no mix — **`gemini-3-flash-preview`** (660 messages), via
**Gemini CLI 0.47.0** (`@google/gemini-cli@0.47.0`). Its transcripts (Apr 7–8)
cover the deployed iteration, so this attribution is exact.

## Reproducibility line for the paper

> The Gemini schedule was produced by `gemini-3-flash-preview` (Gemini CLI
> 0.47.0). The Claude dual-bump was produced by Claude Code v2.1.0; the exact
> per-iteration model is not retained, but the run's recoverable sessions used
> `claude-opus-4-5-20251101` as the primary model (`claude-opus-4-6` appears
> only in later continuation sessions, postdating the schedule), so the
> dual-bump was generated by Opus 4.5 or Sonnet 4.5, most likely the former.

## Method

`grep -oh '"model":"[^"]*"' *.jsonl | sort | uniq -c` over the archived Claude
transcripts; `"model"` field in the Gemini session JSON; versions from the
transcript `version` field and `npm ls -g @google/gemini-cli`.
